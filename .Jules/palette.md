## 2024-05-22 - Improved screen reader interpretation for symbol icons and fixed keyboard focus visibility
**Learning:** Screen readers may misinterpret basic symbol characters (like '↑', '↓', '←', '→') or they may be confusing for users if read literally as symbols. In addition, interactive elements built without explicit focus indicators (like tailwind's `focus-visible` ring) provide poor navigational context for keyboard users.
**Action:** Always provide explicitly localized and descriptive text via `aria-label` when using symbol icons or basic text characters for button content. Additionally, ensure `focus-visible:outline-none focus-visible:ring-2` (or equivalent styles) are applied to all interactive controls so keyboard navigation is visibly obvious.## 2024-05-24 - Accessibility and pause interaction improvements for Snake Game
**Learning:** Found that visual grids representing game boards can create excessive noise for screen reader users if not explicitly hidden from accessibility trees. Additionally, found that while keyboard interactions (like hitting space to pause) are often prioritized in games, maintaining functional parity for point-and-click or touch interfaces (like tapping the 'Jogar' button to pause) is critical for broader usability.
**Action:** Always add `aria-hidden="true"` to decorative or complex visual elements that do not provide meaningful semantic structure to screen readers. For game loops, ensure primary call-to-action buttons correctly reflect and toggle state across all input modalities (mouse, touch, keyboard). Added `aria-live` to dynamically updating game state text to keep screen reader users informed.
